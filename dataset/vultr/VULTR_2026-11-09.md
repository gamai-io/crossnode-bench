# Vultr real multi-region fleet — 200 rounds (2026-11-09)

One Contabo host plus eight Vultr `vc2-1c-1gb` instances (Ubuntu 24.04) in
Frankfurt, Amsterdam, London, Madrid, New Jersey, Chicago, Dallas, and Los
Angeles. Each node runs a token-protected HTTP agent (`node_agent.py`,
systemd `gama-node-agent`, port 8787, `X-Token`). Same 16 tasks, 200 rounds.

## Honest run — 9 nodes
- records: **25,600**
- passed: **25,600 / 25,600 (100%)**
- false success: **0**
- latency: p50 **64.8 ms**, p95 **325.1 ms**
- evidence sha256: `960b661424b2c2a147ad2179d15aeab357a34ce6e45b3e8564066fe824e87049`

## Controlled liar run — 10 nodes (one MockLiar)
- records: **28,800**
- passed: **28,400 / 28,800 (98.61%)**
- false success: **400 (1.39%)**
- all 400 on `vultr-lax-liar`, tasks P1 (missing program) and P2 (missing app)
- latency: p50 **171.3 ms**, p95 **332.7 ms**
- evidence sha256: `372851594aae1ee554a46b817a0c466fad3edda4f3e9a0ecff2df9a081789674`

## Caveat
The liar is a controlled `MockLiar` wrapper around a real Vultr node; probes are
synthetic and run only on nodes exposing a `probe` attribute. This is a
detection test on real infrastructure, not a field false-success rate.
